# 学习档案保存邮件告警

同步异常必须同时在网页显示，并通过独立的健康上报载荷进入服务端告警链。错误的完整学习档案不会被复制到告警请求中，避免一个不合法字段同时阻断保存和预警。

## 告警规则

- 数据校验失败、数据库拒绝、本机存储失败、保存回执异常：进入严重告警。
- 普通同步失败持续 5 分钟：告警。
- 待确认答题持续积压 10 分钟：告警。
- 服务端每 5 分钟独立比较档案与答题日志中的完整事件和数量；发现不一致、重复、清空或档案行消失：告警。
- 同一故障合并一封预警，恢复后发送一封恢复确认。严重异常进入告警后，实际发信等待下一次定时检查，通常不超过 5 分钟。

时间阈值以服务端首次观察时间为准，不依赖客户端时钟。健康上报不含单词、答案、原始错误信息、邮箱或密钥，按登录账号隔离。邮件收件人从已验证的账号邮箱读取，发送服务复用现有 Resend 和学习日报发件人配置。

浏览器身份按账号持久保存，关闭再打开后仍能清除同一个待同步告警；不同设备的失败不会被另一台设备的正常状态掩盖。同类故障按账号合并。失联且空队列的旧状态可以退出活动告警，但不会被当作已恢复；恢复邮件要求明确正常上报或云端日志检查通过。

## 发送可靠性

发送前持久保存待发通知，领取通知采用事务租约。只有邮件服务返回消息 ID，且通知审计保存成功，才标记成功。失败保留在队列重试，不把接口调用当成邮件已发。重试使用同一通知 ID 作为 Resend 幂等键；供应商幂等窗口为 24 小时，长于该窗口的无法确认结果可能再次发送。

告警函数仅接受服务端定时任务密钥，不能从浏览器公开调用发邮件。用户只能上报自己的健康状态，不能指定收件人、邮件正文或发送凭据。密钥保留在 Supabase Secrets/Vault，不进入 Git 或网页。

私有告警表启用 RLS 且不向客户端授予访问。健康上报 RPC 有意使用固定搜索路径的 SECURITY DEFINER，在函数内从 auth.uid() 获取账号并校验参数；只有 authenticated 可以调用。发信领取和完成 RPC 仅允许 service_role。安全顾问关于该健康 RPC 可由登录用户调用的提示属于预期设计，权限回归确认不能读写其他账号或直接发送邮件。[对应顾问说明](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable)。

## 可观测性边界

正常断网时网页保留答题并提示，联网后继续同步和上报。完全断网期间无法立即发送云端邮件。此定时任务位于 Supabase 数据库内；如果整个数据库或项目停机，定时任务也无法运行。它能发现学习保存故障和数据不一致，不能代替服务外的可用性监控。

部署必须验证客户端失败上报、数据库阈值/去重/恢复、发送失败重试/并发租约，以及一封明确标注测试的真实邮件。不能仅部署函数便宣称邮件已接通。
