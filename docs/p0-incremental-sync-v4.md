# P0 修复：真正的 V4 增量同步

## 问题与验收标准

此前 V3 每次提交/返回完整词库与历史，并重新投影全部词条。真实 Chrome 4827 词、1676 条事件的请求约 367 万字符，多次 HTTP 500/数据库超时；仅优化重复请求不能阻止历史增长重新放大问题。

V4 要求：首次初始化/灾难恢复可读取完整基线；之后上传新增答案、变化词条及小型设置，按持久游标拉取变化；服务端不再按每次答题重写完整快照。真实保存故障继续报警。

## 实现

- `learning_delta_sync.js`：独立、无新增依赖的增量客户端。维护与未确认 UI 状态分开的云端确认基线；上传本地差异；回执必须同时确认事件 ID 与已返回的事件。丢包后重发同一事件；游标/epoch 冲突先读取变化再合并重试。
- 每批最多 50 个词条、50 条事件、50 个删除标记；客户端按 UTF-8 100 KiB 拆批，服务端拒绝超过 128 KiB 的单批。单条超限明确报错并保留本机原件。
- 游标落后时每页最多四个变化版本组，逐页保存确认基线并继续；没有把很久未同步积累的全部历史作为一包返回。游标记录保存在 IndexedDB，重新打开继续读取变化。
- `db/p0_incremental_sync.sql`：词条分行、事件独立追加、版本游标。常规按时间追加的答案只处理新事件和受影响词；乱序补交只重算受影响单词的当前 epoch 历史。迁移前旧答案仍参与乱序校验，原基线计数与连对语义保留。没有重写 `reader_sync_state.vocab_master_progress`，旧快照作为迁移输入保留。
- 初始化保留旧学习记录、积分和忽略词。未导入过的删除标记也持久保留，后续导入不能复活。旧格式证据按 V3 原规则区分 baseline/answer，不能把旧备份计数变成新答题。
- V4 初始化后拒绝旧 V3 全量写入，提示刷新；ReadingMaster 的当前读写协议不写该字段，因此不受阻。
- `db/p0_incremental_sync_monitor.sql`：严重一致性监控切换至独立事件引用/哈希、词条及计数投影；仍检查缺失和篡改，不因旧快照停止更新而误报。告警阈值和通知频率未更改。
- RPC 仅作用于 auth.uid()；私有表启用 RLS、撤销客户端表权限；正常客户端不能直接写基线、计数或日志。

## 已执行证据

所有数据库测试都在生产引擎的独立事务中执行并回滚，不向真实学习者添加测试答案。

- `tests/test_incremental_sync_database.sql`：计数不可伪造、重复事件不重复计分、乱序与迁移前历史、旧证据分类、版本冲突、永久删除、旧 V3 写入拒绝、无变化空响应、分页/大小限制。
- 合成 10000 条历史后新增一条答案：服务端仅返回 1 词+1 事件、响应小于 5 KiB，测试耗时约 9 ms；100000 条历史变体约 72 ms。该数字是单次数据库测试，不是长期 p95 或浏览器端到端耗时。
- `tests/test_learning_delta_sync.cjs`：10000 条历史后新增一个答案请求约 306 字符；120 条答案拆成 50/50/20；UTF-8 按大小分批；旧游标多页读取无丢失；缺失回执拒绝；游标重置/冲突、丢包重试和删除标记。
- `tests/test_learning_delta_ui.py`：实际 HTML 加载增量模块，真实 Chromium IndexedDB 提交并刷新恢复 10001 条事件，重开使用已保存的版本游标。
- `tests/test_cloud_rescue_ui.py`：真实 React 答题流程；两种本地库都不可写时，云端正常、提交后丢回包、回执缺失三个场景；刷新后唯一答案、正确次数 1、10 分。
- `tests/test_learning_indexeddb_sync.py`：跨页、部分回执拒绝、保留未确认项、刷新恢复、其他账号隔离及事务中止。
- `tests/test_incremental_sync_monitor_database.sql`：旧快照滞后不误报；日志/引用/词条缺失、载荷篡改和错误计数仍能报警；删除词的历史仍受审计。
- 用当前最大真实档案做回滚初始化测试：4831 词、1676 事件，首次迁移读取约 553 ms；首次完整基线约 4.16 MB，此后不再走完整档案协议。

## 边界

首次读取、用户主动完整导出及本机历史缓存仍与累计数据量相关。乱序答案需要重放该词的相关历史；独立完整性审计会定期扫描日志。普通网络同步、单批请求和常规新答案处理不再随着全部学习历史线性扩张。不能将这些验证写成“无限数据量永不失败”；网络中断、浏览器主动清除和服务停机仍须保留明确失败状态与本机待确认事件。

上线顺序为数据库 V4+监控原子迁移、客户端发布、真实浏览器核实 V4 RPC 请求/回执及持久游标。旧版标签页应刷新；不能直接回滚到不理解 V4 的旧客户端和旧快照。
