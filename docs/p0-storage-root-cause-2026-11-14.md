# P0：VocabMaster 占满同源 localStorage

日期：2026-11-14。影响：同源 ReadingMaster 空间预警及旧版学习记录写入配额异常。用户按 P0 定级。

## 事实与边界

用户提供的 ReadingMaster 排查截图显示：VocabMaster 主数据约 6135 KiB、旧恢复备份约 3234 KiB，同源合计约 9401 KiB，前两项约占 99.7%。这些是截图中的字符串估算，不是本次直接读取用户 Edge 的实测，也不是浏览器配额的精确计量。旧恢复备份的准确键名未提供，不推断其具体生成操作。

ReadingMaster 已迁移数据库，截图中两道答案已保存、待保存为零；历史控制台错误不能证明当前仍在失败。本故障修复针对 VocabMaster 大体积数据继续占用同源共享空间的问题。

## 根因

1. 将词库、学习状态、不可变答题历史和恢复副本放入容量受限的 localStorage。不同路径的同源应用共享该空间，项目名称和路径不能隔离配额。
2. 历史与完整单词定义持续增长，导入留档还会增加完整副本。去重压缩依赖定义完全相同，动态时间等字段变化使压缩收益不可靠。已有 1000 条变化资料测试压缩后仍为原大小的 99.4%。
3. 前次修复只在写入满额后转入 IndexedDB，没有主动迁出旧的大项并释放副本。它保证部分答题继续可用，却没有解除对其他同源应用的空间挤压。
4. 既有测试证明满额后答题可保存，没有把“正常新写入不使用 localStorage”和“旧大项迁出后释放”作为验收条件。

## 最终方案

- 主档案和每条答题事件直接写 IndexedDB，不再将 localStorage 作为首选或回退数据仓库。
- 账号切换备份、旧格式导入留档、PDF 留档进入 IndexedDB。
- 启动及同步刷新时扫描 vocabmaster_ 旧数据；只迁移本应用数据，不触碰 ReadingMaster 或其他项目。
- 同一个 IndexedDB 写事务内检查目标键；遇到不同内容保留现有值并另存 legacy-copy。提交后重新读取并逐项精确比较，全部通过才按原值再次比较并删除 localStorage 原件。
- 中断、事务失败、验证失败时原件保留；下次启动重试。删除阶段发现旧值变化时不删除，以便下一轮迁移。旧版本页面必须关闭或刷新，避免重新写回。
- 保留小型声音偏好、同步设备标识及登录设置。阅读器生词投递仍依赖现有 localStorage 联动协议，不能单方面删除；它不承载主学习档案，但大量投递仍有容量边界，需两项目联合迁移协议才能完全去除。
- 本地数据库不可写时继续走既有云端灾备；只有有效回执及返回历史确认该事件后显示成功。网络和所有持久存储都不可用时明确失败，不假报保存成功。

## 防复发与验收

新增迁移回归测试覆盖：原副本完整迁入、释放旧键、重复执行、冲突保留、事务中止保留原件、其他应用隔离，以及新持久写入不触碰 localStorage。既有真实 Chromium 测试覆盖实际填满 localStorage、答题和刷新恢复、跨页面同步、部分确认、两个本地库都不可写、云端回包丢失重试不重复计分。

新增 GitHub Actions 每次 push/PR 自动运行上述关键存储回归。不得将学习数据重新加入 localStorage 写入路径；任何修改必须保持这些测试通过。仓库仍保留部分仅供旧格式兼容测试使用的同步辅助函数，生产答题与主档案走异步 durable 路径。

不能承诺浏览器空间永久无限、用户永不清除数据或旧版本页面永不再写入。可验证保障是：新版主学习数据不再增长 localStorage；迁移提交并核对后释放旧占用；失败不丢原件、不假报成功。用户原浏览器实际释放数值须加载新版后在该设备确认，隔离测试不能替代。

## 发布与回滚

仅提交本故障相关文件，不包含工作区既有词库及数据库告警修改。入口版本更新为 20261114-p0-indexeddb-primary。GitHub Pages 从 main 发布；发布后比对线上 HTML 与本地内容并用线上整页重复真实配额测试。证据见 tests/test_storage_migration_p0.py、tests/test_learning_indexeddb_sync.py 和 outputs/recovery 下浏览器测试结果。

回滚不能直接回到不读 IndexedDB 的旧版本，否则已迁移档案可能不可见；应保留 IndexedDB 读取和云端救援能力，以前向修复为主。迁移不删除 IndexedDB 中的历史与备份。
