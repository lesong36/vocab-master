# P0 云同步超时：根因、修复与证据

## 根因与实际风险

localStorage 满额和云同步超时是不同故障。生产 authenticated 角色的 statement_timeout 为 8 秒。云端约 4.3 MB、1676 条历史的档案全量写入时，触发器重新校验事件、重建词状态和积分。积分原实现每个事件与逐渐增大的 JSONB 对象连接，重复复制导致二次方增长。相同档案重试也触发完整重建，形成锁等待和反复超时。不是缺索引：事件主键、账号时间索引和单词 epoch 索引均已存在。邮件重复由告警生命周期另行放大，不能以降噪代替同步修复。

风险是本机独有答案迟迟没有云端副本，跨设备滞后；本地数据被清除且尚未上传时可能丢失。已核对生产云端快照及独立日志：1678 对 1678，逐条内容差异零。该核对不能证明所有设备没有待上传记录。

## 实施

1. `db/p0_sync_performance.sql` 将积分流水改为有序批量聚合，只连接一次；保留既有积分及基线覆盖次序、有效范围、类型检查。
2. RPC 对与已锁定规范档案完全相同的输入快速返回；只排除服务端 `_sync` 字段，其余全部比较。鉴权、epoch 校验、锁和日志回执保持不变。有任何真实字段变化仍走完整保护。
3. 客户端失败后的自动重试采用 15、30、60、120 秒封顶退避，成功重置。失败状态和健康心跳继续上报，不因退避显示已恢复；待确认事件仍保留。
4. 未修改告警阈值、未关闭邮件、未提高生产超时阈值、未修改真实学习记录。

## 验证

生产数据库中事务内替换函数、执行测试后回滚，测试通过再部署数据库迁移。`tests/test_learning_sync_production.sql` 适配线上账号自动建档触发器，覆盖基线不重复计分、重复事件、篡改拒绝、离线乱序、回执、账号隔离、管理员恢复和 5001 条历史不截断。`tests/test_cloud_rescue_database.sql` 证明重复提交一条答案只记一次、准确 10 分。所有合成账号最终回滚，残留零。

`tests/test_sync_performance_database.sql` 对当前最大真实档案测试规范重试、元数据修改和一条新答案，写入在子事务回滚；保留耗时和回执检查，无真实答案写入。超过 8 秒明确失败。测试结果有负载波动，不能称为长期 p95：

| 场景 | 修复前 | 已部署修复后 |
|---|---:|---:|
| 相同规范档案重试 | 4462 ms | 269–334 ms |
| 有元数据变化 | 16400 ms | 实测 4127–6850 ms |
| 新增一条答案 | 未单独记录 | 实测 4487–5531 ms |

部署后再次核对：1678 条快照与 1678 条独立日志，内容差异零。浏览器事务/跨页面/部分确认测试，以及云端救援、丢失回包重试、无效回执拒绝测试通过。客户端真实 effect 测试验证退避期间不重复写请求、失败上报仍有效、成功重置退避。

## 边界与后续验收

本次消除了积分二次方复制和相同请求重复重建。真实修改仍走全量档案保护，耗时尚有增长空间；不能宣称任意数据量、任意并发下永不超时。跨浏览器同时大量写入、服务端持续高负载需要后续压力和运行窗口验证。若仍超时，必须继续改造为按新增事件/受影响词计算的协议；不能靠关闭报警或提高超时掩盖。完整日志比对和严重告警继续运行。

独立日志若遭管理员直接破坏，相同档案快速返回不会主动修复；日志回执仍只确认实际存在的事件，独立一致性监控仍负责告警。

## 第二轮真实页面复核与追加修复

第一轮上线后，真实 Chrome 请求仍有 12–17 秒 HTTP 500，故第一轮不能判为故障解除。生产日志定位到词条投影及存档差异计算；真实请求为 4827 词、1676 事件、3671031 字符。导出本地备份与云端逐词核对显示：已有内容一致，云端还可能包含本地旧副本缺少的词。因此只接受整份档案完全相等的快速路径覆盖不足。

追加 `db/p0_sync_stream_words.sql`：

- 逐词返回投影并在单次聚合中构建主档案和原值差异，避免不断追加大数组和再次按完整词表构造大对象进行差异检索。
- 针对旧副本，只有所有提交词条与事件均与规范档案已有条目完全相同、其他可写元数据相同、投影已被云端覆盖时，才能直接返回完整云端档案。没有丢弃云端额外词条/历史；任意新增或改变仍进入原完整保护。
- 停用这两个延迟敏感函数内部的 JIT，未提高超时限制；单独停用 JIT 复测仍失败，不能将它写为单独根因或充分修复。
- `tests/test_sync_covered_retry_database.sql` 在 authenticated 角色及 8 秒限制下提交只含前 10 词和前 10 事件的旧副本，确认返回完整规范档案不变、只确认提交事件，实测约 338 ms。完整数据库回归再次通过。

追加部署后，真实 Chrome 页面已观察到“学习档案已由云端确认保存”，对应 HTTP 200、端到端 11058 ms；之前同页失败请求仍保留，不能把历史日志当作新失败，也不能把这一次成功当作长期稳定证明。部署后快照/独立日志仍是 1678/1678，差异零。该端到端耗时包含网络和序列化，不等于数据库执行耗时。
